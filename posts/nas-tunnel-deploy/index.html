把 Android 手机变成全球可访问的媒体 NAS

起因

一台 OnePlus Ace 2 Pro，456GB 存储，14GB 内存，24 小时在线。跑着 Termux。

为什么不把它变成一个 NAS？

目标很明确：

  • 浏览器访问的文件管理器
  • 通过自有域名全球可访问
  • 支持媒体播放、在线编辑、分享链接
  • 稳定运行，故障自愈

4. 前端优化历程

问题：文件列表永远在加载

症状：页面打开后一直显示 spinner，API 正常返回但 renderList() 不执行。

排查：

根因：doUpload() 函数中，try/catch 的括号不匹配：

一个多余的 } 让整个 <script> 块解析失败，页面上所有 JS 都不会执行。

上传卡在 100%

原因：Flask/Werkzeug 默认把上传文件写入 /tmp，再交给 handler。Termux 的 /tmp 空间有限，大文件写满后静默失败。

修复：

同时改用 f.save() 替代手动 stream.read() 循环，增加 try/except 返回 JSON 错误而非 HTML。

6. 最终状态

完整的页面功能：

  • 文件管理器 (/) — 列表/网格/画廊视图、右键菜单、拖拽上传
  • NAS 仪表盘 (/nas) — 系统状态、磁盘详情、实时刷新
  • 网络工具 (/net-tools) — IP 检测、DNS 查询、Ping
  • 管理面板 (/manage) — 服务控制、一键重启
  • 文本编辑器 — 右键任意文件 → Edit Text → 保存
  • 媒体播放器 — 右键音频/视频 → Play/Stream
  • 分享链接 — 右键 → Share Link → 24h 有效 + QR 码

经验总结

  1. 移动网络不可靠 — 不要假设连接稳定，用 watchdog 兜底
  2. 让工具自动选择协议 — --protocol auto 比指定 quic/http2 更稳定
  3. Flask 单线程是隐型瓶颈 — threaded=True 一行代码解决
  4. JS 括号是魔鬼 — try/catch 的 } 位置错误能让整个页面挂掉
  5. runit 比 systemd 更适合嵌入场景 — 轻量、简单、Termux 原生支持
  6. 二进制 XML 注入 — 不知道 aapt 的 android.jar 有多老之前，别尝试在 Termux 上编译 APK
